# Exodus on NEAR: Agent Guidelines

Welcome to Exodus on NEAR. This file provides guidelines, architectural context, mathematical invariants, and working rules for any AI agent or engineer collaborating on this codebase.

---

## 1. Project Overview & Hackathon Context

- **What is Exodus?** Exodus is a permissionless fixed-yield protocol on NEAR Protocol, porting the Pendle V2 logit curve AMM. It splits yield-bearing Liquid Staking Tokens (LSTs such as stNEAR, LiNEAR, and demo MockLST) into:
  - **Principal Token (PT):** Zero-coupon bond that redeems for 1 NEAR worth of LST at maturity. Implemented as a NEP-141 token directly by the market contract.
  - **Yield Token (YT):** Claims all staking yield generated by 1 NEAR of principal until maturity. Tracked via an internal ledger inside the market contract.
  - **Single Contract AMM:** Each market contract is its own PT NEP-141 token, holds the YT ledger, and executes logit curve AMM swaps.
- **Hackathon:** Built for the **NEAR HACKATHON** (submission deadline: 14 Nov 2026, 23:59 UTC).
- **Mandatory Disclosures:**
  - **Exodus on Canton:** Prior hackathon submission (Daml, permissioned, HackCanton S3 2nd place). The NEAR codebase is a complete rewrite. Disclose in README.

## 2. Technology Stack & Pinned Versions

- **Smart Contracts (Rust):**
  - `near-sdk`: `5.30.1`
  - `near-contract-standards`: `5.30.1` (NEP-141, NEP-145, NEP-148)
  - `cargo-near`: `0.23.0`
  - `near-api` / `near-sandbox`: `0.8.7` / `0.4.0`
  - Target: `wasm32-unknown-unknown`
- **Math Engine (`crates/exodus-math`):**
  - Pure Rust workspace crate, `no_std`-friendly, no `near-sdk` dependency.
  - 18-decimal fixed-point arithmetic (`FP_ONE = 1e18`) with 256-bit intermediate precision.
  - High-precision Taylor expansion for `ln` and `exp`.
  - Pendle V2 logit curve pricing, dynamic anchor adjustment, and bounded binary search.
- **Backend (Rust):**
  - `axum` (REST API), `tokio`, `sqlx` (PostgreSQL), `near-api` (RPC view calls and keeper transactions).
- **Frontend:**
  - React 19, Vite, TypeScript, `@hot-labs/near-connect` (wallet adapter).

## 4. Core Protocol Invariants & Rules

1. **No Floats on Chain:** All rates, indexes, and calculations use fixed-point integers (`u128` / `i128`). Token amounts use their native decimals (24 decimals for NEAR and LSTs). The index uses 18 decimals (`1e18 = 1.0 NEAR`).
2. **Rounding Rules:** Always round in favor of the protocol:
   - PT / YT minted: round down.
   - LST (SY) out on redeem, swap, or claim: round down.
   - LST in required on exact-out trades: round up.
   - YT interest accrued: round down.
   - LP shares minted: round down; LP burned: round down tokens returned.
3. **Value Conservation Invariant:** The contract's LST balance must at all times cover:
   $$\text{Contract LST Balance} \ge \text{Pool SY} + \frac{\text{PT outside pool} + \text{YT principal}}{\text{py\_index}} + \text{Reserved Interest} + \text{Treasury SY} + \text{Pending Refunds}$$
4. **User Exit Guarantee:** Emergency exits must never be blocked by pausing or market expiration:
   - `redeem_py` (burn equal PT + YT for LST): always available.
   - `redeem_pt` (redeem PT post-maturity): always available after expiry.
   - `claim_interest` (claim accrued YT yield): always available.
   - `remove_liquidity` (withdraw LP pro-rata): always available.
   - Pausing only disables new risk-taking (`mint_py`, `swap_exact_sy_for_pt`, `swap_exact_pt_for_sy`, `add_liquidity`).
5. **Index Freshness Check:** State-changing methods require `index_epoch == env::epoch_height()`. If stale, calls abort with `INDEX_STALE: call refresh_index`.
6. **NEP-297 Events:** Emit standard JSON events for all state changes (`mint_py`, `redeem_py`, `redeem_pt`, `claim_interest`, `swap`, `add_liquidity`, `remove_liquidity`, `index_updated`, `market_matured`, `paused`, `unpaused`).

## 5. Development & Testing Commands

```bash
# 1. Run all workspace tests (backend, exodus-math, market, mock-lst, sandbox)
cargo test --workspace

# 2. Run only math tests
cargo test -p exodus-math

# 3. Run market contract unit tests
cargo test -p market

# 4. Run sandbox lifecycle integration tests
cargo test -p sandbox-tests

# 5. Build optimized market contract WASM (skip host ABI linking on Windows)
cargo near build non-reproducible-wasm --no-abi --manifest-path contracts/market/Cargo.toml

# 6. Build mock-lst contract WASM
cargo near build non-reproducible-wasm --no-abi --manifest-path contracts/mock-lst/Cargo.toml
```

## 6. Pair-Programming Guidelines with Ayoub

- **Decision Maker:** Ayoub is the technical decision-maker and code reviewer. Explain concepts clearly and simply, but never hide architectural details, tradeoffs, or risks.
- **Mandatory Approval Gate:**
  1. Inspect existing code using read-only tools.
  2. Explain the problem, root cause, and behavior.
  3. Present options visually (Mermaid diagram, table, or schema).
  4. Propose the simplest sufficient solution with exact scope and tests.
  5. Wait for explicit approval before modifying files or running state-altering commands.
- **Simplicity First:** Write obvious, maintainable code. Do not introduce premature abstractions, unnecessary design patterns, or extra dependencies.
- **Post-Implementation Review Guide:** Always provide a clear summary of what changed per file, control flow, testing instructions, problems hit, and next steps.
- **Conventional Commits:** Propose clear commit messages (`feat:`, `fix:`, `refactor:`, `docs:`, `chore:`). Never add AI co-author signatures or trailers.
